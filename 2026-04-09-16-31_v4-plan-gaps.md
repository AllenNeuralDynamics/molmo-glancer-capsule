## v4 gaps — to resolve during implementation

### G4. `save_prompt_templates()` not mentioned (~140 lines, 1093–1234)

This function saves all prompt templates to `results/prompts.md` at agent startup. It needs
updating for: the new OLMo system prompt, the restructured action schema, the single-action
decision prompt, and the new Molmo2 imaging context block. Could silently produce stale/wrong
output if skipped.

**Now tracked in:** deep-dive §12 prompt templates checklist item #6.

---

### G5. Imaging context block omitted from first-look (Phase 1)

§15.6 of the deep-dive says the imaging context block should be added to all Molmo2 interpret
prompts. But Phase 1 ("capture + interpret initial view") is described with no mention of it.
The first-look interpret call should get the imaging context block too.

**Now tracked in:** deep-dive §12 prompt templates checklist item #5.

---

### G6. OLMo token usage not wired up

`ask_text_olmo()` is defined in the checklist but its return format wasn't specified. The current
`ask_text()` returns `(text, token_counts)` and this flows into `save_outputs()` →
`token_usage.json`.

**Now resolved:** deep-dive §12 checklist item #2 specifies `ask_text_olmo()` returns
`(text, token_counts)` matching `ask_text()` shape.

---

### G10. `crossSectionScale` availability for imaging context block

§15.6 computes `um_per_pixel = view_spec.get("crossSectionScale", ...)` for the imaging context
block. This field is written into the action by `validate_action()` via `resolve_zoom()`. The
imaging context block can only be built **after** validation runs — a dependency the plan doesn't
state explicitly.

**Status:** ✅ Resolved by architecture. Step 2 outputs JSON → `validate_action()` resolves
zoom/coords → step 3 crafts vision instructions with validated action data (including
`crossSectionScale`). The step ordering enforces the dependency naturally.
